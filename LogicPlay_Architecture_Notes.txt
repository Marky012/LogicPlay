LOGICPLAY SYSTEM - COMPREHENSIVE ARCHITECTURE DESIGN
===================================================

1. ARCHITECTURE OVERVIEW: Client-Server & PWA Model
--------------------------------------------------
LogicPlay utilizes a decoupled, modern web stack focusing on high-performance interactive elements on the client side, backed by a fast, asynchronous server. The application is designed as a Progressive Web App (PWA) to ensure accessibility across desktop and mobile devices.

2. PRESENTATION LAYER (Frontend)
--------------------------------
The visual and interactive component of LogicPlay.

*   Framework & Build Tool: React.js bundled via Vite. Chosen for its extremely fast Hot Module Replacement (HMR) and optimized production builds.
*   Styling: Tailwind CSS. Enforces a premium, consistent design system (utilizing custom branding like the primary `#4F46E5` indigo and vibrant `#10B981` emerald greens).
*   Core Interactive Engine: p5.js / Canvas API. Responsible for the drag-and-drop logic gate placement, wire routing, and real-time signal flow animation. This offloads heavy computation (circuit evaluation) to the user's browser, freeing up server resources.
*   State Management: React Context API and custom hooks to manage authentication state, active classroom contexts, and the current state of the logic board.
*   PWA Capabilities: Workbox is integrated for service worker generation, enabling offline caching of static assets and potential offline circuit play in the future.

3. LOGIC & API LAYER (Backend)
------------------------------
The central processing unit that handles data validation, business logic, and security.

*   Framework: FastAPI (Python). Chosen for its asynchronous capabilities, speed, and automatic Swagger/OpenAPI documentation generation (crucial for rapid frontend-backend integration).
*   Authentication: JWT (JSON Web Tokens) with passlib for secure password hashing. Protects API routes, ensuring students can only submit to their enrolled classes, and teachers can only manage their own classrooms.
*   Machine Learning Integration (Planned/Active): Scikit-learn (as referenced in README). Used for the ML-powered auto-grading system, capable of analyzing student circuit submissions (JSON representations) against known logical truth tables to compute an automatic score.

4. DATA PERSISTENCE LAYER (Database)
------------------------------------
Where all system state is permanently stored.

*   Engine: SQLite (Development/MVP Phase).
*   ORM: SQLAlchemy. Provides an object-oriented bridge to the database, allowing Python models (Users, Classrooms, Assignments) to be seamlessly translated into SQL tables.
*   Data Structure Highlights:
    *   Relational Integrity: Strong Foreign Key constraints between Users (Teachers) and their Classrooms/Assignments.
    *   NoSQL-like Flexibility: Utilizing `JSON` column types in SQLite to store complex, nested objects like a student's `circuit_data` (gate positions, connections) and `badges` list, avoiding overly complex join tables for these specific features.

5. SYSTEM COMMUNICATION PATTERN
-------------------------------
1.  User Action: A student tests their circuit on the frontend Canvas.
2.  Evaluation Request: The React frontend structures the circuit diagram into a JSON payload and sends an asynchronous HTTP POST request to the FastAPI backend.
3.  Server Processing: The FastAPI endpoint receives the payload. It may use the ML component (Scikit-learn) or custom logical evaluation functions to determine the circuit's accuracy.
4.  Database Transaction: The backend saves the `Submission` record (including the generated score) to the SQLite database via SQLAlchemy.
5.  Response: FastAPI returns a JSON response to React containing the score, points earned, and any new badges.
6.  UI Update: React updates the UI, showing the "Mission Complete" modal and updating the student's profile level.
